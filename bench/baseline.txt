# micro-forge perf baseline — regression guard (PERF-METHODOLOGY.md §4)
#
# Usage (advisory soft gate):
#   cmake --build build-rel --target micro-forge-bench -j$(nproc)
#   taskset -c 2-5 ./build-rel/bench/micro-forge-bench --baseline bench/baseline.txt \
#       800000 8000000 11
# Prints PASS/REGRESS per scenario but exits 0 — perf is noise-sensitive, so
# this never hard-fails CI. Re-run to distinguish a noise dip from a real
# regression; after an *intentional* perf win, bump these medians upward.
#
# Conditions: RelWithDebInfo (-O2 -g), pinned cores (taskset -c 2-5),
#   warmup=800000 measure=8000000 reps=11, reported value = median of reps.
# Established 2026-06-28 after the perf campaign (document/notes/019-021):
#   +54/+57/+51% over the original Debug/-O0 baseline.
# 2026-07-31 bump after JIT-readiness perf work (document/notes/045): the
#   coordinator WeakPtr→raw-ptr + NVIC has_pending_irq cache — the 56% of
#   end-to-end time a translation cache can't reach — cut per-step overhead
#   roughly in half; end-to-end ~doubled (~50M ips, within 1.4× of the STM32
#   72 MHz native rate). Values pinned at ~median×0.85 so the 15% tolerance
#   absorbs WSL scheduling jitter (uart/tim dip to ~35M).
#
# tolerance: regression flagged when now/baseline < 1 - tolerance
tolerance: 0.15
